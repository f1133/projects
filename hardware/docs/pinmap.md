# Actuator node — MCU pin map

Generated by `tools/pinmap.py` from `tools/spec.py`, so it cannot drift from
the netlist the boards are built from. Regenerate with:

```
cd hardware/tools && python3 pinmap.py
```

## What this proves, and what it does not

It proves, against the board itself, that no pin is asked to carry two nets and
that every function the design declares has a pin. It does **not** prove the
peripheral is available on that pin in silicon — that comes from the
STM32G431's alternate-function table, which is why every row carries its AF
number for CubeMX to confirm.

## The three that will bite you

**PB4 is NJTRST out of reset.** It carries `DRV_nFAULT`. In CubeMX set
`SYS → Debug` to **Serial Wire** (not "JTAG 5-pin" or "Serial Wire + JTAG"), or
the fault line is held by the debug block and reads whatever the JTAG state
machine leaves there.

**PB8 is also BOOT0.** It carries `FDCAN1_RX`. R6 pulls it down so the part
boots from flash; the transceiver's RXD then drives it as an ordinary input.
The consequence is that you cannot enter the ROM bootloader by strapping BOOT0
high while the transceiver is powered — use SWD on J5, which is why J5 exists.

**PB0 is ADC1_IN15, not IN12.** The build console's table says IN12. Set the
channel from CubeMX's own pin view rather than from the console, or `VBUS_SENSE`
reads a different channel than the one that is wired.

## Peripheral allocation

| Peripheral | Use |
|---|---|
| TIM1 CH1/2/3 | three-phase PWM, centre-aligned, complementary not needed (the Mini takes single-ended IN1/2/3) |
| ADC1 | injected group on IN2/IN4 triggered by TIM1, regular group for NTC and Vbus |
| FDCAN1 | joint bus, 8 MHz crystal is what makes the bit timing legal |
| I2C1 | motor-mounted magnetic encoder on J6 |
| SPI1 | unused; broken out on J8 for an encoder or driver upgrade |
| RCC OSC_IN/OSC_OUT | 8 MHz HC-49S |
